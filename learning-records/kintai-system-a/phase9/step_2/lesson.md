## 概要

上長ユーザー（superior: true, admin: false）が仕様書通りに動作するかテストする。
上長は「申請を受け取る側」でもあり「自分でも申請する側」でもある。

---

## 何をするのか（考え方）

### 上長ユーザーの特殊な立場

上長は2つの役割を持っています：

1. **申請を受け取る側**: 一般ユーザーからの残業申請・勤怠変更申請・所属長承認申請を承認/否認する
2. **申請する側**: 自分の勤怠も管理し、自身より上位の上長に申請できる

「係長が部下の申請を承認しつつ、自分も部長に申請する」というイメージです。

## 確認したコマンド

```bash
# 上長ユーザーのアクセス制限テスト
# 自分のページ（OK）
curl -s -b /tmp/superior_cookie.txt http://localhost:3000/users/52 -o /dev/null -w "%{http_code}"
# → 200

# 一般ユーザーのページ（上長は閲覧可能）
curl -s -b /tmp/superior_cookie.txt http://localhost:3000/users/2 -o /dev/null -w "%{http_code}"
# → 200

# /users（管理者専用ページ → 弾かれる）
curl -s -b /tmp/superior_cookie.txt http://localhost:3000/users -o /dev/null -w "%{http_code} %{redirect_url}"
# → 302 http://localhost:3000/
```

## 学んだこと（まとめ）

- 上長ユーザーは `superior: true` フラグで識別される
- `admin_or_correct_user` メソッドは「本人または上長」を許可するため、上長は他ユーザーのページを閲覧できる
- 管理者専用ページ（/users）は上長も閲覧できない（`admin_user` で制限）
